### Talk Overview

- Guest lecture (Laura, from Physical Intelligence / PI) on data and evaluation for robotic foundation models
- Three-part structure: data for generalization, evaluating general models, evaluation as data

### Data Sources and Generalization (PI0.5)

- Goal: get a robot to clean a kitchen or bedroom in a totally new home, zero-shot
- Four data sources considered:
  - Mobile teleop data: most relevant, most expensive
  - Lightweight static arms: cheaper, more environmental diversity, different embodiment
  - Web data: no robot actions, but object recognition and instruction understanding
  - Internal lab data: large volume, controlled settings, not home environments
- Environment diversity experiment:
  - 3 training environments: poor zero-shot generalization
  - ~20 environments: significant improvement
  - ~100 environments: matches in-domain specialist performance
- Pre-training on ~10,000 hours of diverse robot data was critical
  - Without it, in-domain performance roughly halved
  - Zero-shot generalization essentially fails entirely
- Ablation results (starting from full recipe):
  - Removing cross-embodiment lab data: drops from ~80% to ~50%
  - Removing static multi-environment data: drops to mid-50s
  - Removing web data: only a few points, not statistically significant (but this misses the full story)

### Open-Ended Evaluation in Real Environments

- Controlled evals only capture a narrow slice of what the model has learned
- Key anecdote: robot asked to put an oven mitt in a drawer, instead grabbed a towel and hung it on the oven handle
  - The towel was never planted as part of an eval; robot found it independently
  - Laura had just spent time failing to get a specialist model to do exactly that task
  - Rich environment gave the expressive policy a chance to reveal unexpected capability
- Stress-testing examples:
  - Moving laundry basket around; robot searched for it when out of sight
  - Continuously adding condiments to a table; robot locked onto spills specifically, not indiscriminate wiping
- Key insight: open-ended interaction reveals what the model has truly internalized, not just what it was trained to do
- Distinction between open-ended and controlled evals:
  - Controlled evals: essential for quantifying differences and answering specific research questions
  - Open-ended: best for understanding capability frontiers and choosing research problems

### Compositional Generalization and Web Data

- Promptable robot demo: deployed in an unseen home, guided only by language, ran for ~1 hour without physical intervention
- Web data’s value only revealed when measuring instruction following, not task success rate
  - Out-of-distribution objects (goggles, guitar-shaped spoon): model with web co-training could identify and manipulate them
- Air fryer sweet potato task (PI0.7):
  - No mobile robot teleop data collected for this task
  - Model succeeded by combining: Droid episodes (closing air fryer, moving basket), human video, web data
  - Likely transferred “put object into compartment” from drawer data
- Cross-embodiment folding:
  - Shirt folding demos collected only on ARC robots
  - No laundry folding data on UR5 bimanual setup
  - World model translated folding knowledge; VLA figured out physical execution from other task experience

### World Model Architecture (PI0.7)

- Pairs VLA with a world model to incorporate action-free data (human video, web, static images)
- World model takes current observation + language instruction, imagines a useful future state
- VLA uses robot experience to physically achieve that imagined state
- Compared to backing out pseudo-actions via hand detection: visual interface produced more decisive behavior
- Generalization depends on both sides: world model must propose a useful target; VLA must be steerable enough to act on it

### Evaluation as Data: Real-World Deployment (PI Star 6)

- Shifted from segmented evals to real jobs: coffee bar, laundry folding in homes, box-building in a chocolate factory
- Problems only visible in long-horizon deployment:
  - Long tail of rare real-world events (e.g., cardboard sheets stuck together)
  - Success rate alone insufficient; throughput (successful completions per hour) is the practical metric
- Deployment data loop:
  - Collect on-policy data during real jobs (successes, failures, recoveries, human interventions)
  - Train next model on this data
  - Coffee bar: throughput improved from ~15 to ~29 drinks/hour after one iteration
  - Laundry: similar ~2x throughput improvement, even when deployment environment differed from training environment
- Autonomous deployment data matters more than human interventions alone
  - Holding out autonomous data and training only on interventions: no throughput lift
- PI0.7 also trained on PI Star 6 deployment data; model improved directly out of the box

### Open Questions and Q&A Highlights

- How to use failure data in training: empirical, task-specific; no bulletproof general recommendation
  - Value function trained on labeled good/bad actions; policy training on failure data is case-by-case
  - Depends heavily on how good the initial deployed policy was
- Robot hallucination and safety: acknowledged as critical, especially for robots in human environments
  - No strong answer yet; expected to evolve alongside capabilities
- Deciding what to test: largely intuition built from continuous model interaction, analogous to vibe-checking a new LLM
- Base movement commands: early prompting used explicit directional commands; now model understands semantic goals (“move to the fridge”)
- Base and arm actions are jointly modeled, not separate

### Parting Takeaways

- Things assumed to be hard (long-horizon autonomy, compositional generalization) turned out more tractable than expected
- Data collection framing shift: not “cover every task,” but “build a broad set of reusable low-level behaviors”
- Model architecture should flexibly ingest diverse data: multiple action spaces, open-ended language, image conditioning
- Iterative loop: collect broad experience, deploy, observe, learn, repeat
- Rich evaluation environments are as important as rich training data; both give the model a chance to surprise you
