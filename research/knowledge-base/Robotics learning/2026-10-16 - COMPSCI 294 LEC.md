### Code as Policy: Approaches Overview

- Three main paradigms for using coding agents in robotics:
  - **Runtime loop** (CAP Agent 0, RATS): generate new code every turn, heavy per-episode cost
  - **Offline debug, fixed program** (Aspire): debug per task offline, freeze one program at inference
  - **Evolved repository** (ROW): evolve a full code repo offline, zero LLM calls at deploy time

### CAP Agent 0 and RATS

- CAP Agent 0: training-free baseline, synthesizes task-agnostic skill library from successful rollouts
  - Robust to instruction wording changes (token-level perturbation vs. OOD for end-to-end models)
  - 2-3 min per try; latency expensive due to live LLM calls
- RATS (Berkeley, June): structured play-and-learn skill acquisition
  - Proposer, executor, and reflector agent teams work offline; skills frozen at test time
  - More rigorous execution: plan, verify, convert to code, evaluate outcome
  - Likely slower than CAP Agent 0 due to extra verification steps
  - Risk: skills may overfit to specific environment/object distribution

### Aspire and ROW

- Aspire (Nvidia, July/Aug): offline trace-guided repair
  - Collects fine-grained primitive traces (inputs, outputs, return status, before/after frames)
  - Evolutionary search if repair fails; best program frozen per task
  - Outperforms turn-by-turn zero-shot code generation; reusable skills transfer across tasks
  - Practical for fixed known tasks (e.g., factory stations); runtime latency reduced but not eliminated
- ROW: evolves a multi-file repository as policy
  - Reflection, mutation (Codex), and Pareto-based acceptance phases
  - 0 LLM calls at inference; ~3 min/task average (similar to CAP Agent 0 in practice)
  - ~70% on RoboSuite vs. 68% for CAP Agent 0 multi-turn, but gains uneven across tasks
  - Concerns: overfitting (trains on 10/100 trial IDs), object-swap collapse, high search cost, simulation only

### Anthropic Study: LLM Capabilities in Robotics

- Tested four control interfaces: direct control, programmatic (Python), RL supervision, pre-trained policy steering
- Simple control: Python controller outperforms direct control and RL supervision
- Locomotion: only Opus 4.5 could balance humanoid; none recovered humanoid from collapsed position
- Manipulation (7-DOF arm): best model achieved only 5.5% full-task success rate
- Pre-trained policy + LLM: significantly better than direct control, but LLM sometimes degrades an already-competent VLA
  - LLM helps on novel tasks where VLA alone fails; unreliable at knowing when to trust vs. override
- Bottlenecks identified: spatial/geometric understanding, long-term state tracking, latency
  - Adding visual info (depth, segmentation) didn’t consistently help; explicit geometric cues (compass, cursor) did
  - Reasoning did not consistently improve performance
  - Latency: 2-15s without reasoning, 15-60s with reasoning; physics must be paused in simulation

### End-to-End Learning: ACT and PI Models

- ACT (Action Chunking with Transformers): predicts action sequences from camera images and joint positions
  - Uses conditional VAE + temporal ensembling; ~50 demos per task, ~5 hrs training on one GPU
  - 84-96% success on precise tasks; only ~20% on Velcro threading; each task needs its own policy
- PI 0.5: generalizes across unseen homes
  - 400 hrs of mobile robot data from ~100 homes plus web data; ~56-step action chunks
  - Performance approaches in-distribution model at ~100 training locations
  - Other robot data improves task performance; web data helps with unfamiliar objects
- PI 0.7: generalist matches specialist on tested tasks without task-specific post-training
  - ~80% on shirt folding (no folding demos); expert operators ~81%
  - Learned physical skills increasingly generalize; coding agents have not yet matched this

### Discussion: Convergence, Task Fit, and OOD Generalization

- Task fit summary:
  - Code better for: multi-step reasoning, structured planning, failure recovery, instruction robustness
  - Learned policy better for: tight contact, deformables, reaction speed, continuous control
  - Deformables: coding agents score ~0%; VLAs handle them; contact-rich tasks require real-time tactile feedback
- OOD generalization:
  - VLAs brittle out-of-distribution but improving with more pretraining data
  - Code loops may overfit tuned constants but the verification/recovery loop generalizes well
  - Code-over-VLA (e.g., LLM loop over PI 0.5) currently top performer on Libero benchmark
- Convergence argument: VLA as low-level motor primitive (“cerebellum”), coding agent as high-level planner (“prefrontal cortex”)
  - Code can call any controller (fine-tuned, NPC, servoing) not just discrete actions
  - New robot arm: rewriting code with agent likely cheaper than collecting new demos (compute hours vs. human hours)
- Open questions raised:
  - Is 0% on contact tasks an API ceiling or a code ceiling?
  - If program complexity must match VLA performance, does interpretability survive?
  - Should we adapt programs or weights for new environments?
